# 对上一届报告的复核，以及我们如何借鉴

来源：DataExploration_Practicum_FinalProjectReport.pdf。下文页码按PDF物理页计；报告印刷页码通常少一页。已重新提取全文，并核对第11、15、17页的页面。

## 1. 报告中的rolling不是同一件事

- 第11页，§5.9：GBR预测使用30天历史缓存，每一步将预测值加入缓存，递归产生14天预测。这是**预测输入缓存的滚动**；该段没有说明每7天重新估计模型。
- 同页：GBR使用各ZIP内部85/15时间切分，再合并到四个区域训练。它并非我们已经固定的60天训练、每7天重训设计。
- 第15页，§6.6：GMM选取2020年6—8月和2021年1—3月作为训练区间，分别预测2020年9月、2021年4月。这是两个历史阶段的前向评估，文中不足以还原持续每周重训的完整协议。
- 第9页，§5.5与第17页，§7.1：wave-specific CUSUM按已指定的wave_start/wave_end重新拟合；报告自己承认波次边界需要预先指定。它不能直接作为无需未来信息的自动线上检测协议。

**我们的决定：不更换已接受的规则。** 仍是60个日历日、每7天重新拟合、每天直接预测未来1/2/3天。三天预测分别拟合，不将前一天的预测递归填入后续输入。每次训练的未来目标必须在拟合日已经成熟。

## 2. 最有用的借鉴

| 报告中的思路 | 我们的落实方式 |
|---|---|
| 不只报告全年平均，比较不同疫情阶段 | 对相同预测按Q2/Q3/Q4、月份、horizon比较；时间分组固定，不根据谁胜出再挑日期 |
| 汇集地区数据，避免每个稀疏ZIP单独训练 | 我们继续合并585个ZIP训练，保留地区身份；不临时照搬其四区聚类 |
| 展示数量、变化指标和检测表现的不同角色 | 保留trajectory MAE主指标；方向/形状/变化量/加速度作补充；预警仍待独立定义 |
| 多方法各有长处，不能只给一个总排名 | 完成RF后比较三模型的数量误差、形状、分组和空间残差，报告trade-offs |
| 对估计与比较记录不确定性 | 在相同日期和ZIP路径上算配对误差差异，7天日期区块bootstrap，14天敏感性；探索性HAC/Holm辅助，不使用独立ZIP假设 |
| 图旁写key finding | 每张比较图旁的文字必须对应已计算数值；不能把汇总曲线贴近解释成逐ZIP形状准确 |

## 3. 不直接照搬的结论

- 第11页的“±1.96×RMSE×(1+0.10×step)”属于经验构造。没有覆盖率验证，不把它当成已校准的95%预测区间。我们的配对误差置信区间也不是单条病例预测区间。
- 第15页按lag系数大小推荐lag1，不等于已经证明其样本外误差最小。报告提到的lag7 p=0.07不能替代整个模型的预测评估。
- 第8页§5.3的Wilcoxon使用候选日期前后各14天，因此至少需要未来14天才能确认；可用于回顾核验，不能作为当前预测日已知输入。
- 第16—17页CUSUM检测率高，但部分波次典型检测延迟为9—19天。高检测率不等于提前预警；还要报告提前/延迟、误报和漏报。
- 该报告县级真实COVID与ZIP合成管道并存。我们有真实NJ ZIP发病记录，评价的分母和空间粒度不同，不能直接把他们的准确率与我们的trajectory方向一致率比较。
- 更换报告中的目标、时间或指标，不能把之前查看过的2021—2023年恢复为未接触过的独立测试。我们继续称为回顾性时间评估。

## 5. 目前结果给我们的分析问题

XGBoost在2020年整体MAE略低，但在实际首尾发生变化的路径上并未改善；严格方向/形状一致率较低。下一步重点不是盲目扩大模型复杂度，而是检查：第三个模型能否重复这种数量与形状的权衡？该现象是否主要与零病例路径、日期阶段或严格零阈值有关？完成这些后再冻结候选方案，讨论后续年份和预警层。
